# 第三阶段：语义、关键词、时间与人物检索

此前记忆预选依赖最近记录，相关的旧喜好可能还没进入语义判断就被截掉。现在先检索当前频道全部仍有效的记录，再选择和核对来源。

## 检索过程

1. 读取当前频道 active、未过期、有证据且未涉及退出记录者的记忆，不受旧250条读取窗口限制。
2. 使用现有 Codex、关闭搜索，生成1–4个语义相近的检索表达、可验证人物ID，以及当地时间的日期范围。例如“喝的”可以检索饮品、茶、咖啡；扩展词只是线索，不是事实。
3. 本地使用中文双字切分、英文数字词和 BM25 相关度计算，融合原问题和扩展查询的排名。人物约束、发言日期约束先筛选；相关度相同时再参考人物、人工确认状态和时间。最多60个候选进入下一步。
4. 沿用第二阶段：语义选择最多6条，重新读取 Discord 来源，校验归属和原文，再做语义核对。找不到匹配可以不使用记忆。原文、当前纠正和手动自述优先。
5. 持续话题同样从最多30个保留快照中排序取3个；超过3个时调用查询规划，随后仍核对最多36条来源，不能把未核实摘要当成当前话题。

没有增加向量服务、embedding API、数据库服务或模型下载。这里的语义能力来自 Codex 查询扩展和候选复核；本地是词汇检索，不是向量相似度。

## 人物与时间

- 人物以 Discord 用户ID为准。新观察到的有效普通消息维护频道内的显示名/用户名历史，每人最多5个别名，180天未更新清理；可结合当轮原文和已有成员缓存识别名称。旧记忆不会凭空补出用户名，缺少映射时可用明确 @。重名无法消歧则不返回该次记忆候选。
- “上周在群里说过”按证据消息的当地日期过滤，起点包含、终点不包含；指定人和指定日期必须在同一条证据上匹配。
- 单个明确的“这周一”“上周”“昨天”“上个月”等由程序计算日历范围，避免模型把一天扩大成整周；复杂组合范围仍由模型解析。
- “上周发生的事”不按发言时间硬过滤，由语义选择判断描述的事件时间。不能假装存有独立事件日期字段。
- 人工更正/确认只使用最新管理证据的日期，不能拿旧证据日期查询出修改后的偏好。当前数据模型不保存同一主题的完整偏好版本历史。
- 所有检索仍在当前频道内。清空、退出记录同时移除本频道人物名称映射；不会建立跨频道关系画像。

## 保留、失败与管理

移除旧20条偏好/50条共同经历的数量删除，沿用90/180天有效期及7天候选期。只改变今后的保留，不恢复过去已经裁掉或删除的记录。话题仍最多30个、30天未更新过期。保留量随有效期内的新记忆增长。

记忆查询规划最长12秒；失败时回退到原文关键词和能确定的人物，由后续语义选择继续判断原问题。整段可选记忆检索最长50秒，失败不阻断正常回答；正常回答先预留调用容量。记忆最多新增一次查询规划调用，话题候选超过3个时也可新增一次，仍计入 `/用量`。

已有数据库直接读取；新建 `memory_people` 元数据表，无需重建记忆。检索不写回或重新提取旧内容。管理命令按完整保留记录查找，旧编号也可查看来源、更正或删除；列表仍只展示最近10条，尚无历史分页界面。

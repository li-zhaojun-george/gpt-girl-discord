# 多频道自动记忆

前一阶段的多频道对话与私密 / 指令已由用户验收，并先保存至GitHub检查点 `55cb1b6e49fe16313cad29a83f9ed2934f47a683`。本阶段将现有23个已启用聊天位置的 `AUTO_MEMORY_CHANNEL_IDS` 配置为与 `OBSERVED_CHANNEL_IDS` 相同，涵盖18个文字频道及5个语音频道的文字区。没有语音录音或识别。

从开启后收到的新文字消息提取普通喜好与共同话题，不回读频道历史。原有敏感内容过滤、来源校验、候选状态、过期清理和每人每频道数量上限不变。共同回忆表示群里讨论或共同确认的事情，不表示机器人线下参与。没有把旧频道的记忆复制到其他频道。

每个频道独立保存与检索记忆，用户归属由Discord ID确定。新频道首次开启时发一条静默功能说明，已有通知不会重复。开启自动记忆不改变原有主动分享范围或安静时段。

多个频道同时有待整理消息时，按最早待处理消息排序；繁忙频道的新批次不会一直抢在其他频道前面。正常聊天仍可打断整理，批次保留后重试；不同频道的原文、证据和已有记忆不混用。

## 操作与验收

- `/状态`：查看当前频道自动记忆是否开启。
- `/记忆 自动`、`/记忆 共同`：查看本人喜好及本频道共同回忆。
- `/记忆 来源`、`/记忆 更正`、`/记忆 删除`：核对和修订归属于自己或自己参与的记忆。
- `/记录 停止`：清除涉及自己的记忆和提醒，并停止在当前频道记录新消息；其他频道的设置独立。`/记录 恢复` 不恢复已删除内容。

111项自动测试通过，新增覆盖两个频道同一用户不同自述的独立落库与重新打开数据库、拒绝其他频道证据、繁忙频道不饿死其他批次、分频道退出和新频道通知幂等。实际频道验收应在游戏聊天或学习聊天发一条普通偏好，空闲约30秒后用 `/记忆 自动` 查看编号和内容，再用 `/记忆 来源` 检查原消息；繁忙时需等待聊天结束。

回退时恢复原 `AUTO_MEMORY_CHANNEL_IDS` 并重启即可缩小记录范围；不要删除数据库。源代码、测试和说明提交GitHub，真实配置、记忆数据与备份保留在部署机器。

# 根据语义读取话题上下文

30分钟内存窗口只作为短期缓存，不再决定可理解的聊天范围。旧版依靠“上一句/⬆”等词读取前面三条同作者消息，容易遗漏多人讨论和话题起因，现已移除该逻辑。

Codex后端每次准备生成聊天回复时，先读取当前消息之前的最近15条同频道消息，由关闭搜索/工具的语义判断判断这句话是独立问题、已找到话题，还是需要更早上下文。无需指令、关键词或箭头。“那还值得买吗？”也可以触发继续读取。

若缺少对象、对比项或讨论起因，每轮再向前读取15条，允许跨作者、岔开的话题和超过30分钟的间隔。找到当前话题起点及必要来回后停止。模型只能选择程序实际读取到的消息ID；代码验证起点、相关消息、焦点和显式回复锚点，再按时间顺序交给回复模型。旧分享、旧错误回答及自动记忆不替换这些实际来源。

Discord回复引用优先重新读取原文。普通语义判断可选择群友发言或GPT娘自己的消息，不默认选择最近的视频或同一个人的三句话。独立问题在首轮停止；上下文不够且无法继续时，明确对话会请用户补充，主动插话则保持沉默。

单次最多向前扫描120条、最近7天消息，最多60秒；这些是防止无限翻阅和长时间占住对话的边界，不是模型用量预算。显式回复可按ID读取指定原文。达到边界仍缺少起因时不编造“已找到开头”。每条原文最多800字符，不下载附件或假装理解图片。

持久化话题阶段增加独立来源入口：自动记忆频道从保留的话题中混合检索最多3个候选，按来源ID重新读取并核对原文（最多36个来源；本轮已读到的消息复用）。这可找回7天顺序扫描窗口之外、仍在30天状态保留期内的话题。核对成功的原文和摘要参与同一次语义选择；最终只把焦点落在已选来源上的话题状态附给回复模型。普通顺序扫描上限仍为120条，总处理超时仍为60秒。来源读取失败时不使用对应摘要，继续依据本次可读原文判断。详见 [TOPIC_STATE.md](TOPIC_STATE.md)。

权限、频道隔离、退出记录与敏感内容过滤适用于回读；模型只能读取当前频道提供的消息，不能自主访问其他频道。回读仅用于本次对话，不写进群聊缓存、完整聊天日志或自动记忆提取队列。来源在检索期间因清空等操作失效时丢弃；之后新发言会重新读取Discord。模型判断调用计入本地用量，原有安静时段、插话冷却和聊天路由仍生效，管理指令不进行此分析。API备选后端未实现该结构化判断。

127项自动测试通过，新增14项覆盖无关键词追问连续翻页、跨作者话题选择、无关视频排除、独立问题停止、显式引用、来源ID验证、权限、退出记录、读取边界、失效结果与计数。实际Codex合成验证：从40条多人聊天中连续读取3页，找到第1条的键盘选购起因，并排除插入的泡面视频；独立质数问题只读1页后停止。实际群聊体验另行验收。

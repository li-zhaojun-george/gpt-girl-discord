# 第一阶段：持续话题状态

目标：在多人聊天、话题穿插和进程重启后，继续理解讨论对象、进展及未完问题。借鉴 MaiBot 的滚动状态组织思路，独立实现；没有复制其代码或增加第三方记忆框架依赖。

## 行为

- 仅在 `AUTO_MEMORY_CHANNEL_IDS` 已启用的频道整理新消息，包括未触发回复的普通聊天，以及成功发出的普通对话回复。
- 空闲达到现有 `MEMORY_BATCH_DELAY_SECONDS`（默认12秒）后，关闭搜索的 Codex 提取器按语义更新多个话题。正常对话可打断整理，未处理批次稍后重试。
- 每个快照保存标题、背景、进展、未完问题、约定、实际来源参与者、原消息ID与内容指纹。原始全文不写入话题表。
- 同一话题的快照可更新；明确完成的问题从 pending 中移除。不同主题分别保存。摘要只是辅助资料，不代表事实核验、离线经历或已创建提醒。
- `/状态` 显示本频道已整理话题数；管理操作仍仅自己可见。

## 恢复与核对

SQLite `conversation_topics` 随现有状态数据库持久化。启动无需导入，已完成整理的状态可直接读取；尚在内存等待整理的消息在强制退出时可能丢失。

生成回复时，从当前频道全部保留的话题中检索最多3个候选，再读取来源，复用本轮已有原文，其余向 Discord 按ID重新读取。每条来源必须仍可读、未退出记录、指纹和作者一致。源消息已删除或修改则移除快照；临时网络错误或权限问题仅跳过，不把错误当删除。普通实时编辑/删除事件保守清空该频道的派生话题状态，并取消在途生成。`清空记忆`／`不记录我` 同样清理该频道的话题快照，避免其他人的摘要间接保留已撤回内容。

语义选择继续决定当前消息是否独立、是否需再回读、哪些原话相关；持久化摘要不能强行改变独立问题的讨论对象。最终只传入与选中焦点相交的话题摘要，旧的无关视频仍被排除。

## 当前边界

- 每频道最多30个快照，30天未更新过期；每个快照最多12条来源，每组状态最多4条。后台待处理队列每频道最多60条，批次最多更新6个话题。高流量时过旧的未处理缓冲可能被覆盖。
- 第三阶段已加入语义扩展、关键词、人物和时间检索；候选超过3个时先做查询规划，再排序取3个核对来源。仍最多保留30个话题，已过期或被替换的快照不能恢复。
- 所有频道继续隔离，不建立跨频道人物画像。
- 不改接话路由、不自主发送跟进、不接入图片理解；长期自动喜好与已选话题的融合仍是下一阶段工作。
- 整理和判断使用现有 Codex 适配器及本地用量计数，没有新增 API 自动回退或日调用限制。

## 验收

154项自动测试通过，其中新增22项覆盖重启、无原文落盘、多话题、结论纠正、完成事项、来源ID验证、频道隔离、保留期、离线编辑/删除、临时读取失败、无权限、未来消息、退出记录、普通聊天静默整理、优先级、取消重试和在途失效。

真实 Codex 合成验收通过：保存多人键盘讨论后，用同一数据库重建运行对象，在没有短期聊天缓存时正确接续“那便宜那款还值得买吗？”，选中键盘原文1–4；随后将“已经买好入门款”的纠正写回原话题，pending 清空。使用模拟 Discord 来源，不发送群消息。实际 Discord 用户体验尚待验收，不能以这些测试代替。

2026-10-30：用户确认第一阶段真实群聊测试没有问题。随后开始第二阶段，相关喜好与共同经历现已接入话题回答，详见 [MEMORY_CONTEXT.md](MEMORY_CONTEXT.md)；以上第一阶段的“不融合长期记忆”描述为当时范围。

## 后续阶段

1. 本阶段：持续话题状态与来源恢复。
2. 人物画像、共同事件和有证据的长期认识；把相关记忆融合进当前话题。
3. 中文语义、关键词、时间和人物联合检索。
4. 接话和主动关心读取统一状态，完善对象判断与分享动机。
5. 多人话题切换、隔天接续、偏好变化和误触发的固定回归评测。

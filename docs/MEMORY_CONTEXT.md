# 第二阶段：让记忆参与当前话题

之前解析到话题上下文后，会把 `social_memory` 全部移除，以防旧分享干扰当前对象。现在继续排除无关分享与旧错误回答，但把经过选择、核对的长期喜好和共同经历与话题原文一起交给回复模型。

## 流程

1. 在当前自动记忆频道读取 active 记忆，排除候选、过期及涉及已退出记录者的内容。人物候选来自当前发言者、明确提及者及选中话题的实际参与者。
2. 第三阶段已将原先按更新时间预选的20/20/20条改为本频道全部有效记录的混合检索，按人物、时间和相关性选出最多60条，详见 [HYBRID_RETRIEVAL.md](HYBRID_RETRIEVAL.md)。
3. 使用关闭搜索的 Codex 按当前问题、已选原文、话题状态和手动记忆选择最多6个已有记忆ID；无相关项时返回空列表。程序验证ID属于实际候选，拒绝虚构或重复ID。
4. 按ID重新读取选中记忆的来源（最多24条，4个并发），检查频道、作者、原摘录、退出状态、敏感内容与权限。公共来源超过2000字则不使用，避免只读截断片段误判含义。明确更正/确认以管理操作的最新证据为准；私密 slash 操作使用数据库内已授权的管理记录，不伪造公开消息。
5. 再以完整可读原文进行语义核对，排除否定、讽刺、转述、含义已改变的旧记忆。不能仅因为原文仍含旧摘录，就认定喜好仍然有效。
6. 回复携带 owner、参与者、摘要及本轮核对的证据。原文和当前需求优先；相关喜好自然影响建议，共同经历仅表示真实交流过，不推断线下共同活动。

## 可靠性与边界

- 选择与核对共最多两次模型调用，第三阶段额外一次查询扩展，均计入现有本地用量；不新增收费API或外部数据库。
- 正常回答先预留调用容量，选记忆不能挤占它。第三阶段记忆流程总超时50秒；读取失败、模型错误或验证不通过时放弃本次记忆辅助，仍可按当前话题回答。
- 清空、编辑、删除、退出记录、更新消息会使在途结果失效；提交给回复模型前还会比较数据库记录是否变化。
- 不把本轮回读来源加入自动提取队列，不反复学习旧消息，不改写用户喜好。今天想换口味只影响当前回答；永久喜好更新仍由原有提取和更正流程处理。
- 各频道仍隔离；尚未引入跨频道人物画像、向量索引或自动关系推断。管理指令继续不调用模型。
- 语义判断仍可能误选；找不到合适记忆时允许不用，不强行展示“我记得”。

## 验收

173项自动测试通过（新增19项），覆盖话题与记忆共存、无关问题、频道与人物归属、共同经历来源、已修改原文及否定语义、私密/公开更正、无权限、退出记录、来源失败、ID校验、在途修改、手动事实优先、关闭搜索和调用容量。

真实 Codex 合成测试通过：

- 当前问题只说“那我适合点哪杯”，结合饮品话题和本人的无糖红茶喜好作出推荐。
- 能选回两人实际参与的饮品讨论，保留两位证据作者。
- 当前明确表示想试试咖啡时，排除旧的红茶偏好。
- 独立询问质数时，不使用饮品记忆。

以上真实模型测试使用合成数据和模拟 Discord 来源，没有向群里发送测试消息。2026-10-30：用户确认第二阶段测试没有问题，开始第三阶段。

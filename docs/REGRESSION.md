# 第五阶段：固定群聊回归

`evals/group_chat.json` 保存合成对话、稳定的用例ID和预期结果。`regression.py` 使用真实的 `GirlBot.on_message`、话题恢复、记忆检索、对象判断与生成流程；Discord 消息、权限和传输由本地模拟，数据库每个用例独立创建。

## 固定用例

| 类别 | 用例ID | 核查重点 |
| --- | --- | --- |
| 多人切换 | switch_keyboard_video | 两人讨论键盘后插入机器人泡面分享，追问仍找到键盘原文 |
| 多人切换 | switch_other_person | 和机器人聊过后转头叫 Ryan，机器人不抢答 |
| 多人切换 | switch_explicit_reply | 明确回复的消息仍是锚点，无关分享不混入 |
| 隔天接续 | next_day_restart | 重建机器人、清空临时状态，凭 SQLite 话题和实际来源恢复讨论 |
| 隔天接续 | next_day_finished | 已完成的选择正确恢复，不把旧待续事项当成未完成 |
| 隔天接续 | next_day_missing_source | 原消息删除后不凭摘要编造，丢弃快照并请求澄清 |
| 喜好变化 | preference_permanent_change | 后来的明确喜好替换同主题旧偏好，使用新证据 |
| 喜好变化 | preference_temporary_override | 今天想换口味影响本次建议，不直接改写长期记忆 |
| 喜好变化 | preference_correct_owner | 提到另一人的不同口味时，仍按说话者要求找回自己的喜好 |
| 误触发 | false_trigger_emoji | 纯反应表情不因为短时接续窗口而收到回复 |
| 误触发 | false_trigger_closed | 结束对话不再调用模型或回复 |
| 误触发 | false_trigger_unrelated_memory | 独立知识问题不牵扯个人饮品喜好 |

合成时间锚定运行当天多伦多中午；消息相对时间固定，避免凌晨运行把30小时前误当“昨天”。用例只验证普通文本能力，不声称看懂表情图片。

## 两层运行

在项目目录执行：

```powershell
# 全部单元测试，包含固定对话的离线回放
.\.venv\Scripts\python.exe -B -m unittest -q

# 离线报告；不调用模型
.\.venv\Scripts\python.exe -B regression.py --output eval-reports/offline.json

# 用当前系统账号的 Codex 登录重放；显式指定本机原生程序和模型
.\.venv\Scripts\python.exe -B regression.py --live --executable C:\path\to\codex.exe --model YOUR_MODEL --output eval-reports/live.json

# 对失败用例独立重复，保留每次结果
.\.venv\Scripts\python.exe -B regression.py --live --case preference_correct_owner --repeat 3 --output eval-reports/owner.json
```

也可通过环境变量 `CODEX_EXECUTABLE`、`CODEX_MODEL` 配置；运行器不会自动读取部署 `.env`，不需要 Discord token。`--case` 可以重复传入；非法或空选择直接失败。退出码0表示所有选中用例完成且通过，1表示存在失败。

- **离线层**使用固定模型返回值作为可控输入，验证程序是否正确读取、过滤、归属、恢复和发送。预写回复不代表模型语义能力；不能把这层称为真实回答质量测试。
- **真实层**将同一批消息交给实际 Codex；预期结果和 `oracle_*` 字段不发送给模型。搜索关闭，不发送 Discord 消息，不改生产数据库，不自动回退到付费 API。消耗现有 Codex 用量。
- **GitHub Actions** 在PR和main更新时运行离线层，Windows/Python 3.11与3.13；不上传凭证，不在CI调用真实模型。工作流使用只读仓库权限。

## 报告与判定

JSON逐例记录：类别、通过/失败、错误原因、实际回复、选中的原消息ID、引用记忆的用户和证据ID、回读来源、模型各阶段结构化输出、耗时及重复序号。另记录模型名、套件SHA256、Python源文件SHA256、运行时间和分类通过数。中途失败保留已完成结果，`completed=false`不能算整套通过。

结构断言直接检查归属、来源、动作、重启后状态、数据库更新和无关记忆排除；答案文本只做明确主题词/禁用干扰词的冒烟检查，不使用另一个模型给自己打分。通过不等于语义在所有表达下都正确，报告里的实际回复仍值得人工检查。

生成报告默认放在忽略提交的 `eval-reports/`。分享报告前确认仍为合成数据；不要将实际群聊原文、昵称或凭证加入公开测试集。增加真实问题的回归时，先匿名改写成小型场景，保留触发逻辑与期望，再同时跑离线与真实层。

## 本轮发现并修正

1. 人物检索之前会用句中出现的名字强制覆盖模型判断，比较别人和自己时可能选错归属。现在保留经过ID验证的语义人物选择，名字匹配只在未指定目标时补充；没有联网或新增人物资料。
2. 上下文解析之前可能把“对象已明确、需要个人喜好”的问题误判为缺少聊天起点，提前要求澄清。现在明确告知解析器后续存在独立长期记忆检索，缺少近期原文不等于没有记忆；对象确实不明或来源删除时仍澄清。

本轮236项离线测试通过，含12个固定对话和5项运行器/判定检查。首轮真实测试11/12通过，暴露第二项问题；修复后针对人物、新偏好及来源删除做两次独立复测，6/6通过。

随后完整12个场景各做两次真实Codex回放：原始判定23/24通过；唯一未通过项实际推荐了“奶咖、拿铁、美式”，属于只匹配“咖啡”造成的词汇误报。将这些等价饮品纳入主题词后，原输出重新核对24/24通过；原始报告和重新判定的报告分别保留，后者标记`review`及`original_errors`，不冒充重新生成的回答。人物、来源、动作和数据库断言没有放宽。

这些结果覆盖固定用例，不代表所有自然语言表达都达到同样准确率。固定用例保留本轮发现的失败条件；新增问题应继续加入套件，而不是只修改人格提示后凭感觉确认。
